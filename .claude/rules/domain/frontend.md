# Domain Rules: Frontend

## WHEN
- 사용자 화면(UI), 상호작용, 상태 관리 코드를 작성/수정할 때
- API 호출/로딩/에러 처리 플로우를 구현할 때
- 접근성/반응형/성능 관련 이슈를 해결할 때

## DO
- 사용자 액션에 대한 로딩/성공/실패 상태를 화면에서 명확히 표현한다.
- 접근성 기준(WCAG AA)을 만족하도록 시맨틱 마크업과 키보드 접근을 보장한다.
- 상태는 로컬/전역 기준을 문서화하고, API 레이어와 UI 레이어를 분리한다.
- API 실패는 사용자 메시지와 재시도 가능 경로를 함께 제공한다.
- 필요 시 코드 스플리팅/지연 로딩을 적용해 초기 렌더 비용을 줄인다.

## DON'T
- 로딩 없는 무응답 상태를 방치하지 않는다.
- API 오류를 콘솔에만 남기고 UI에 숨기지 않는다.
- 전역 상태를 남용해 단순 로컬 상태까지 중앙화하지 않는다.
- 접근성 속성(alt, label, role)을 생략하지 않는다.

## CHECK
1. 주요 사용자 플로우에서 로딩/에러/빈 상태가 모두 표시되는지 확인
2. 키보드 탭 이동과 스크린리더 기본 동작 확인
3. 번들 증가/초기 로딩 악화 여부를 빌드 결과로 점검
