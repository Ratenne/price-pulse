# Domain Rules: Fullstack

## WHEN
- 프론트엔드/백엔드를 함께 수정하는 기능을 구현할 때
- API 계약, DB 스키마, 인증/인가를 동시에 변경할 때
- 배포 파이프라인 또는 운영 설정을 변경할 때

## DO
- 프론트/백엔드/API 계약을 분리하되 변경 영향도를 명시한다.
- 입력 검증/인증/인가를 서버에서 강제하고 클라이언트는 보조 검증만 수행한다.
- DB 변경은 마이그레이션 스크립트와 롤백 경로를 함께 준비한다.
- 환경(개발/스테이징/프로덕션)별 설정 분리를 유지한다.
- 배포 전 모니터링/헬스체크 기준을 확인한다.

## DON'T
- API 스펙 변경을 클라이언트와 서버 중 한쪽만 반영하지 않는다.
- 검증/권한 처리를 클라이언트에만 의존하지 않는다.
- 스키마 수동 수정만 하고 마이그레이션 기록을 누락하지 않는다.
- 운영 환경 민감정보를 코드에 하드코딩하지 않는다.

## CHECK
1. API 계약 변경 시 요청/응답 스키마와 클라이언트 호출부 동기화 확인
2. DB 마이그레이션 적용/롤백 시나리오 점검
3. 배포 전 보안 점검(`/security-gate` 또는 `/secrets-audit`) 결과 확인
