# 외주개발 인계팩 생성

기존 MVP, 화면, 문서를 외부 개발사가 견적·구현할 수 있는 수준으로 정리한다.

## 입력 원칙

- 현재 작업 폴더 안에서 확인되는 자료만 사용한다.
- 불명확한 요구는 추정 구현하지 않고 `확인 필요`로 표시한다.
- API 키, 비밀번호, 개인정보, 고객 원문은 산출물에 복사하지 않는다.
- 물리 제품 제작, 납기, 견적, 성과를 보장하지 않는다.

## 실행

1. `decision-lock.md`, `docs/`, 실제 코드와 화면을 읽는다.
2. `templates/builder/outsource-handoff-pack.md`의 완료 기준을 적용한다.
3. 아래 5개 파일을 `docs/outsource_handoff/`에 만든다.

| 파일 | 목적 |
|---|---|
| `01_기술계획서.md` | 현재 구조, 목표 구조, 기술 선택, 보안·운영 조건 |
| `02_기능요구사항서.md` | 사용자별 기능, 입력·처리·출력, 예외·권한 |
| `03_화면별_기능정의서.md` | 화면 목적, 상태, CTA, API, 반응형·접근성 |
| `04_개발범위_우선순위.md` | P0/P1/P2, 제외 범위, 의존성, 완료 기준 |
| `05_견적요청_체크리스트.md` | 견적 단위, 일정, 산출물, 검수, 유지보수 질문 |

## 완료 게이트

- 모든 기능에 검증 가능한 완료 기준이 있다.
- loading/empty/error/success/permission 상태가 정의된다.
- 인증·권한·개인정보·백업·로그·배포 책임이 명시된다.
- 기존 구현, 신규 개발, 제외 범위가 분리된다.
- 견적사가 질문 없이 알 수 없는 항목은 `발주자 확인 필요`로 모은다.

완료 후 생성 파일과 남은 확인 질문만 요약한다.
