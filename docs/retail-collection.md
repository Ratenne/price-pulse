# 다나와 외 판매처 가격 수집

2026-10-19 구현 및 검증 기록. **다섯 사이트 모두의 자동 수집이 가동된 상태는 아니다.**

## 실제 확인한 범위

| 사이트     | 구현 경로                                         | 실제 외부 요청 결과                                             |
| ---------- | ------------------------------------------------- | --------------------------------------------------------------- |
| 11번가     | 상품 상세 HTML의 JSON 데이터 + DOM 교차 검증      | `8620117214`에서 일반 판매가·배송비·새상품·무옵션 확인 성공     |
| 쿠팡       | 연결한 상품 상세 페이지의 명시적 schema.org Offer | 검색/상세 HTTP 403. 실사이트 파싱 성공 미검증                   |
| G마켓      | 동일                                              | 검색/상세 HTTP 403. 실사이트 파싱 성공 미검증                   |

| 네이버쇼핑 | 연결한 판매 페이지의 명시적 schema.org Offer      | 검색 HTTP 418. 확인된 상품 연결 없음. 실사이트 파싱 성공 미검증 |

네이버·쿠팡·G마켓·옥션용 공통 구조화 데이터 파서는 **그 사이트가 필요한 필드를 실제로 제공한다는 보장이 없다.**
접근 제한이 해제되어도 배송비/상품상태 필드가 없으면 실패한다. 실제 페이지 응답을 확보한 뒤 전용 파서를 보완해야 한다.
403/418/429는 재시도하지 않고 해당 실행에서 같은 사이트의 나머지 요청도 중단한다.
검색엔진의 과거 가격·검색 요약은 현재가로 저장하지 않는다.

API 키는 필요하지 않은 구현이다. 네이버 [공식 검색 API](https://developers.naver.com/docs/serviceapi/search/shopping/shopping.md)는
Client ID/Secret이 필요하고 응답의 lprice만으로 배송비 포함 총액을 확정할 수 없어 현재가 경로에 연결하지 않았다.
판매자용 API를 전체 판매처 검색 API로 가정하지 않는다.

## 저장과 화면 기준

- `retail_product_links`: 기존 GPU와 판매 URL의 검증된 연결. 제조사·정확한 모델·OC·메모리·유통사/보증을 확인한다.
- `retail_price_observations`: 각 성공 관측의 상품가·배송비·시각·수집 방식. 월별 이력과 별도 저장하며 동일 URL/관측 시각은 중복 저장하지 않는다.
- `retail_current_offers`: URL별 마지막 유효 가격. 과거 관측이 현재가를 덮어쓰지 않는다.
- `product_current_prices`: 최근 12시간 안의 유효 관측 중 사이트별 최저가와 전체 배송비 포함 최저가를 조회한다. 화면 요청은 외부 사이트를 호출하지 않는다.
- 배송비가 확인된 판매처가 있으면 그중 최저가를 쓴다. 기존 다나와 값은 배송비가 불명확하므로 비교에서 제외하고, 유효한 판매처가 없을 때만 기존 다나와 참고가로 대체한다. **새 판매처 가격이 다나와 참고가보다 높을 수도 있다.**
- 상세 화면은 사이트별 총액·배송비·확인 시각·원문 링크를 표시한다. 수집된 가격 중 최저가이며 시장 전체 최저가를 보장하지 않는다.
- 다나와 월별 차트·분석·검토 제외 규칙은 유지한다. 신규 수집 가격을 과거 월에 소급해 채우지 않는다.
- 품절이 확인되면 그 판매 URL의 현재가를 제거한다. 네트워크/파싱 실패는 이전 성공 시각을 갱신하지 않고 최대 12시간 뒤 만료시킨다.
- 상품명/연결 검증 버전이 바뀌면 이전 버전의 가격을 비교에서 제외한다. 같은 판매 URL을 다른 GPU로 자동 재연결하지 않는다.

새 상품의 일반 구매가 + 일반 국내 주소에 1개 배송하는 비용 기준이다.
중고·리퍼·벌크·해외구매·렌탈·조건부 할인은 제외한다. 도서산간 추가비는 비교 총액에 포함하지 않는다.
옵션 추가금, 배송비, 품절 여부를 확정할 수 없으면 저장하지 않는다.
11번가는 `selPrc`를 사용하고 쿠폰·회원·카드 할인가 및 적립금은 사용하지 않는다.

## 적용 순서

1. 기존 `001`~`004`가 있는 DB에 `database/008_retail_prices.sql`을 먼저 적용한다. 재실행 가능하다.
2. 해당 DB의 `DB_URL`, `DB_USERNAME`, `DB_PASSWORD`, `DB_SSL`을 실행 환경에 설정한다. 기존 현재가 배치와 동일하다.
3. `config/retail-links.json`의 연결을 등록하고 수집한다. 기본 파일에는 공개 검색으로 찾은 실제 URL 4건이 있으며 네이버 URL을 지어내어 넣지 않았다. 기존 카탈로그의 다나와 상품 코드와 이름까지 일치하는 GPU에만 연결된다. 없는 GPU는 경고하고 건너뛰며 가격도 생성하지 않는다.
4. API 코드와 화면을 배포한다. **008 적용 전에 새 API를 배포하면 뷰가 없어 조회가 실패한다.**
5. GitHub 기본 브랜치에 반영하면 `Refresh Retail Prices`가 KST 00:27·03:27·…·21:27 실행된다. 실제 가동 여부는 Actions 결과로 확인한다.

`005`의 `pc_*`는 별도 확장 설계이며 이번 경로의 의존성이 아니다. 기존 정책 승인 상태를 변경하지 않는다.
신규 가격 테이블/뷰의 공개 역할 접근은 막고 서버 DB 연결을 사용한다.
이번 작업에서 운영 DB SQL 적용, 배포, GitHub Secrets 설정은 수행하지 않았다.

프로젝트 `source` 폴더에서:

```powershell
# 외부 요청만, DB 불필요: 부분 실패 시 종료 코드 2
node --import tsx server/scripts/refreshRetailPrices.ts --probe

# 기존 GPU와 정확히 일치하는 연결 등록 후 수집
node --env-file=.env.local --import tsx server/scripts/refreshRetailPrices.ts

# 별도 검증한 URL 목록 사용 (파일 형식은 config/retail-links.json)
node --env-file=.env.local --import tsx server/scripts/refreshRetailPrices.ts --links path/to/links.json

# 등록된 URL과 listing ID/최근 실패 조회
node --env-file=.env.local --import tsx server/scripts/refreshRetailPrices.ts --list

# 적법하게 확보하고 검증한 API/피드/파일 관측 입력
node --env-file=.env.local --import tsx server/scripts/refreshRetailPrices.ts --import path/to/observations.json
```

`pnpm refresh:retail`로도 실행할 수 있다. 배치당 기본 100개 URL, 요청 간 최소 1.5초,
요청 제한 10초, 응답 최대 5MB이다. 같은 URL은 최근 시도 후 3시간 동안 다시 수집하지 않는다.
사이트별 URL을 번갈아 처리하며 오래된 시도를 우선한다. 일부 실패/차단/카탈로그 미일치는 종료 코드 2,
DB 오류/잘못된 설정은 1이다. 처리 대상이 없으면 가격 수집 성공으로 기록하지 않고 별도 경고한다.

## 외부 파일 입력

파일은 JSON 배열이다. `listingId`는 `--list`에서 확인한다. 예시 가격과 시각을 현재 가격으로 사용하면 안 된다.
API/파일 제공 측에서 동일 모델·옵션과 일반 구매 조건 및 배송비를 실제로 확인한 값만 넣는다.
모든 행의 형식·모델·시각을 먼저 검증한 뒤, 관측별 트랜잭션으로 저장한다.
DB 오류는 즉시 중단하며 이미 저장한 행은 남는다. 동일 관측 재입력은 중복 생성하지 않는다.

```json
[
  {
    "listingId": 1,
    "title": "등록한 listingName과 같은 전체 상품명",
    "itemPrice": 100000,
    "shippingFee": 3000,
    "currency": "KRW",
    "condition": "NEW",
    "availability": "IN_STOCK",
    "conditional": false,
    "observedAt": "2026-10-19T00:00:00Z"
  }
]
```

배송비 누락/음수/미래 관측/12시간 이상 지난 관측/이름 불일치는 거부한다.
관측 이력의 자동 삭제는 이번 구현에 포함하지 않았다. URL을 대량 추가하기 전에 실제 관측 행 수와 DB 용량을 확인한다.

## 이번 검증 결과

- 타입 검사와 프런트/서버 프로덕션 빌드 통과.
- Vitest 92개 통과, 운영 DB 연결이 필요한 기존 테스트 5개는 미실행.
- 별도 PGlite(PostgreSQL WASM)에서 008 재실행, 비공개 권한, 배송비 포함 최저가 선택, API 조회, 이력 보존, 중복/충돌/과거 관측, 품절/만료/연결 변경을 검증했다. 운영 DB 테스트가 아니다.
- 최종 수집기 실제 요청: 11번가 1건 성공(상품가 882,700원 + 일반 배송비 3,000원), G마켓·쿠팡·옥션 3건 접근 차단. 이 검증은 DB에 쓰지 않았다. 이 가격은 2026-10-19 관측 기록이며 현재 유효 가격으로 하드코딩하지 않았다.
- 현재 작업 환경에 운영 DB 환경변수/로컬 설정 파일이 없어 운영 스키마 적용·가격 저장은 수행하지 못했다.
